# Definition of Done

## Requirements
- [ ] Problem and expected behavior understood.
- [ ] Acceptance criteria identified.
- [ ] Constraints understood.
- [ ] Non-goals identified for non-trivial work.

## Context
- [ ] Relevant instructions read.
- [ ] Relevant PRD/product/architecture/design docs inspected.
- [ ] Existing implementation/tests inspected as needed.
- [ ] Graphify used when architecture/impact was materially uncertain.

## Implementation
- [ ] Existing patterns reused where possible.
- [ ] Scope remains controlled.
- [ ] No unjustified dependency or abstraction added.
- [ ] No unrelated refactor.
- [ ] No debug artifacts or secrets.

## Verification
- [ ] Applicable verification executed.
- [ ] Relevant tests/typecheck/lint/build run.
- [ ] UI rendered/inspected when materially affected.
- [ ] Browser verification performed when the gate requires it.
- [ ] Failed checks investigated rather than bypassed.
- [ ] Final diff and git status reviewed.

## Reporting
- [ ] Completion claims are evidence-based.
- [ ] NOT RUN checks are disclosed.
- [ ] Material limitations are documented.
